# チェックの一覧

このページは、プログラムが使っている定義から作っています（`go run ./cmd/docgen`）。手で直さないでください。

- 重大度: E = エラー、W = 警告、I = 情報。「指定」= 案件のルールに書いた重大度
- 頭の字: V = 値、X = 対向（2 台の間）、G = 生成、M = 移行（旧との違い・対応）、S = 外部一覧、L = 投入ログと反映確認

| ID | 重大度 | 内容 | 直し方 |
|---|---|---|---|
| V-101 | E | 必須の値が空 | 指摘のセルに値を入れます。その設定が要らないなら、行ごと消します。 |
| V-102 | E | 値の形式が型に合わない | 指摘のセルを、その列の書き方に直します（見出しのセルのコメントに記入例があります。アドレスは 192.0.2.1/24 の形、数は半角の数字）。 |
| V-103 | E | 値が範囲の外 | 指摘のセルを、範囲の中の値に直します（範囲は指摘の文と、見出しのセルのコメントにあります）。 |
| V-104 | E | 選択肢にない語 | 指摘のセルを、選択肢の語のどれかに直します（選べる語は指摘の文と、見出しのセルのコメントにあります）。 |
| V-105 | E | 行のキーが重複している | 同じキーの行のどちらかを消すか、キーの列（機器・名前・番号など）の値を変えて別の行にします。 |
| V-106 | E | 参照先がない（ACL 名・IF 名・回線監視の番号など） | 指摘のセルの名前・番号を、参照先の表にあるものに直します。参照先が無いなら、参照先の表に行を足します。その設定が要らないなら、セルを空にします。 |
| V-107 | E | 「機器」列のホスト名が機器シートにない。@グループ名 に当たる機器が 1 台もない | 「機器」列を、シート「機器」にあるホスト名に直します。新しい機器なら、シート「機器」に行を足します。@グループ名 は、シート「機器」の「グループ」列にその名前を書いた機器が要ります。 |
| V-108 | I | 定義にない見出しがある（自由列として読んだ） | 自由列として使うなら、そのままでかまいません。定義にある列のつもりなら、見出しの字を定義の見出し（docs/tables.md）に合わせます。 |
| V-109 | E | 機器シートのメーカーに当たるパックがない | シート「機器」の「メーカー」を、同梱のパックの ID（cisco_ios・nec_ix・nec_qx）か、案件の packs/ に置いたパックの ID に直します。 |
| V-110 | W | 値に全角の英数字、前後の空白、制御文字が含まれる | 指摘のセルを打ち直します（全角の英数字を半角に、前後の空白と改行を消します）。わざとその字を使っているなら、承認します。 |
| V-111 | E | IF 名が、機種のポート一覧にも論理 IF の書き方にも当たらない | IF 名を、その機種にあるポートの名前か、論理 IF の書き方（Loopback0・Tunnel1 など）に直します。 |
| V-112 | E | 生成先のメーカーで書けない語 | 指摘のセルを、生成先のメーカーが書ける語に直します（書ける語は指摘の文にあります）。どうしてもその設定が要るなら、セルを空にして追加コンフィグ（extra/）に書きます。 |
| V-113 | I | 「明示」列が空のため、生成先の既定値で書き出す | 生成先の既定値でよければ、何もしません。値を決めたいなら、指摘のセルに書きます。 |
| V-114 | I | 機種が空、または書いた機種がパックの機種の定義にない | 機種が分かっていれば、シート「機器」の「機種」（更改では「新旧対照表（機器）」の「新機種」）に、パックの機種の ID を書きます（ID は各パックの README の「機種の定義」）。定義に無い機種なら、このままで構いません（情報です。IF 名の確かめと機種の機能の確かめは行われません）。案件フォルダのパックに models.yaml を置けば、機種を足せます。 |
| V-115 | W | 参照先がないが、参照先の表をその機器のメーカーパックがまだ読まない | 参照先の設定は、追加コンフィグ（extra/）に書きます。書いたら承認します。参照が要らないなら、セルを空にします。 |
| V-116 | W | 書いた機種が、パックの機種の定義の ID に似ているが当たらない（打ち間違い） | 「機種」を、指摘に出ている似た ID に直します。ID が正しく、パックの定義に無い機種なら、承認します（IF 名の確かめと機種の機能の確かめは行われません）。 |
| V-201 | E | 同じ機器・同じ VRF の中で、IF のサブネットが重なっている | 重なっている IF のどちらかのアドレスかプレフィックス長を直します。別の VRF に置くつもりなら、「VRF」列を埋めます。 |
| V-202 | W | 案件の中で同じ IP アドレスが複数の IF に付いている | 同じアドレスを持つ IF のどちらかを直します。わざと同じにしている（冗長構成で片方だけが生きる、など）なら、承認します。 |
| V-203 | E | IF のアドレスがネットワークアドレスかブロードキャストアドレス | IF のアドレスを、ネットワークの中のホストのアドレスに直します（/24 なら末尾が .0 と .255 は使えません）。プレフィックス長が違っていないかも見ます。 |
| V-204 | W | スタティック経路のネクストホップが、その機器のどの IF のサブネットにも入らない | ネクストホップのアドレスか、IF のアドレス・プレフィックス長を直します。再帰の経路（別の経路で届くネクストホップ）をわざと使っているなら、承認します。 |
| V-205 | E | 仮想 IP が、その IF のサブネットに入らない | 仮想 IP を、その IF のサブネットの中のアドレスに直します。IF のアドレス・プレフィックス長が違っていないかも見ます。 |
| V-206 | E | ホスト名に使えない文字がある・長すぎる | ホスト名を、英数字とハイフンだけ・63 字までに直します（ほかのシートの「機器」列も同じ名前に直します）。 |
| V-207 | E | ルータ ID（OSPF・BGP）が案件の中で重複している | 重なっているルータ ID のどちらかを、ほかの機器と違う値に直します。 |
| V-208 | I | 有効な IF の説明が空 | IF の「説明」を書きます。説明を付けない決まりなら、そのままでかまいません（情報です）。 |
| V-209 | E | ハッシュ化された秘密の値を、別メーカーの機器に引き継ごうとしている | 新しいメーカーの機器には、ハッシュではなく平文の値を書きます（「形」の列を平文にして、値を入れ直します）。平文が分からないなら、新しいパスワードを決めます。 |
| V-210 | W | ACL・プレフィックスリスト・回線監視が、定義されているがどこからも使われていない | 使わないなら、その行を消します。これから使うなら、使う側（IF・NAT・経路など）の列に名前を書きます。追加コンフィグから使っている・わざと残すなら、承認します。 |
| V-211 | W | ACL に行が 1 つもない。permit の行が 1 つもない | ACL に行を足します。permit の行が無い ACL は全部を止めるので、わざとでなければ permit の行を足します。わざとなら、承認します。 |
| V-212 | W | TCP MSS 調整の値が MTU − 40 より大きい | TCP MSS の値を、MTU − 40 以下に直します（MTU 1454 なら 1414）。わざと大きくしているなら、承認します。 |
| V-213 | E | DHCP の配布範囲・デフォルトルータがネットワークの外。配布範囲が IF のアドレスを含む | DHCP の配布範囲・デフォルトルータを、プールのネットワークの中に直します。配布範囲から、IF 自身のアドレスを外します。 |
| V-214 | W | スタティック経路・冗長化が参照する回線監視の送信元 IF が無効 | 回線監視の「送信元 IF」を有効な IF に直すか、その IF を有効にします。工事の途中でわざと無効にしているなら、承認します。 |
| V-215 | E | IPsec の方式が tunnel_if なのにトンネル IF がない。policy なのに対象通信の行がない（相手が any の行を除く） | 方式が tunnel_if なら「トンネル IF」を埋めます。policy なら、シート「IPsec 対象通信」にそのトンネルの行を足します（相手が any の行は、無くてもかまいません）。方式の方が違うなら、方式を直します。 |
| V-216 | W | 弱い暗号（des・md5・dh1・dh2・dh5）を使っている | 強い暗号（aes・sha256・dh14 以上）に直します。相手の機器が弱い暗号しか使えないなど、変えられない理由があるなら、承認します。 |
| V-217 | E | PPPoE の論理 IF・物理 IF がインタフェース表にない | PPPoE の「論理 IF」「物理 IF」を、シート「インタフェース」にある IF 名に直します。IF の行が無いなら、足します。 |
| V-218 | W | 秘密の値が仮の値のまま | 仮の値を、本当のパスワード・鍵に書き換えます。検証用にわざと仮の値で出すなら、承認します。 |
| V-221 | W | 経路制御の方針の名前（BGP ネイバー・再配布・ポリシールーティング）が、方針の表にない | 方針の名前の打ち間違いなら、指摘のセルを直します。方針がまだ無いなら、シート「経路制御の方針」に行を足します。方針を追加コンフィグ（extra/）に書いているなら、承認します。 |
| V-222 | W | 経路制御の方針が、定義されているがどこからも使われていない | 使うつもりの方針なら、BGP ネイバーの「受信の経路制御」「送信の経路制御」、再配布の「経路制御の条件」、IF の「ポリシールーティング」のどれかに、その名前を書きます。要らない方針なら、行を消します。表の外（追加コンフィグ）で使っているなら、承認します。 |
| V-223 | W | AS パスのリスト・コミュニティのリストが、どの方針からも使われていない | 使うつもりのリストなら、方針の「条件: AS パス」「条件: コミュニティのリスト」にその名前を書きます。要らないリストなら、行を消します。表の外（追加コンフィグ）で使っているなら、承認します。 |
| V-224 | W | 経路制御の方針に permit の行が 1 つもない | 通したい経路があるなら、動作が permit の行を足します（「ほかは全部通す」なら、条件の列をすべて空にした permit の行を、いちばん大きい順番で足します）。わざと全部落としているなら、承認します。 |
| V-225 | W | 経路制御の方針の行に、その使い道では効かない列の値がある | その方針を何に使うかを決めます。ポリシールーティングなら、条件は ACL、動作はネクストホップ・出力 IF で書き、指摘の列を空にします。経路（BGP・再配布）なら、「出力 IF」「経路が無いときの…」の列を空にします。両方に使いたいときは、方針を 2 つに分けます。 |
| V-226 | W | 経路制御の方針の行に、一緒には書けない値・使われない値がある | 指摘の文にある列を直します。deny の行の「付ける値」は使われないので、空にするか、動作を permit にします。コミュニティの条件は、じかの値かリストのどちらか 1 つにします。none はほかの値と一緒に書けません。 |
| V-227 | E | IPv6: DHCPv6 サーバが配るプレフィックス・アドレスの列の組み合わせが合わない | 指摘の文にある列を直します。下流へ配る「元」と「長さ」、有効時間と推奨時間は、それぞれ組で書きます。長さは、元のプレフィックスの長さ以上にします。「上流からもらったプレフィックスから配る」には、同じ機器の WAN 側の IF の「プレフィックスをもらう（DHCPv6-PD）」に書いた名前を書きます。どの列も、「DHCPv6 サーバ（名前）」のある行に書きます。 |
| V-228 | E | RIP: IF・再配布の行に RIP の行がない。認証の列の組み合わせ・RIPng の行に書けない列 | 指摘の文にある列を直します。IF・再配布の行があるなら、シート「RIP」にその機器・その種類（ipv4・ipv6）の行を足します。認証は「認証」と「認証キー」を組で書き、「認証キーの番号」は md5 のときだけ書きます。版・認証は RIP（ipv4）だけの設定なので、RIPng（ipv6）の行では空にします。 |
| V-229 | E | 回線監視: 監視先がアドレス・ネットワークの形でない。送信元アドレス・監視の出口のネクストホップが監視先と別の種類（IPv4・IPv6） | 監視先を、icmp ならアドレス（192.0.2.1・2001:db8::1 の形）、route ならネットワーク（192.0.2.0/24・2001:db8::/32 の形）で書きます。「送信元アドレス」「監視の出口のネクストホップ」は、監視先と同じ種類（IPv4 なら IPv4、IPv6 なら IPv6）のアドレスにします。 |
| V-231 | E | IPsec の自分の ID・相手の ID が「種類:値」の形でない | 「自分の ID」「相手の ID」を「種類:値」の形に直します。種類は address（アドレス）・fqdn（名前）・email（メールアドレスの形）・keyid（自由な文字）です。例: fqdn:rt-a01.example.com。ID を使わない（アドレスで見分ける）なら、空にします。 |
| V-232 | W | IPsec の行に、その IKE の版では使わない値がある | 指摘の列は、その行の「IKE の版」では使われません。版が正しいなら、指摘のセルを空にします（IKE のモードは版 1 だけ、PRF・相手を確かめる鍵は版 2 だけです）。値の方が正しいなら、「IKE の版」を直します。 |
| V-233 | W | IPsec の相手監視の再送回数・再送間隔・送り方があるのに、間隔がない | 相手監視を使うなら「相手監視の間隔」を書きます。使わないなら、再送回数・再送間隔・送り方のセルを空にします。 |
| V-234 | E | IPsec の相手アドレスが、アドレス・any・名前のどれでもない | 「相手アドレス」を、相手のアドレス（例 203.0.113.20）、any（相手のアドレスが決まっていない）、相手の名前（FQDN。空白なし）のどれかに直します。 |
| V-235 | E | L2TP の「IPsec の設定名」が指す IPsec の行が、受け口を守る形（方式 policy・相手 any・モード transport）でない | 「IPsec の設定名」には、L2TP の受け口を守る IPsec の行の名前を書きます。その行は、シート「IPsec」で、方式を policy、相手アドレスを any、IPsec のモードを transport にします（L2TP/IPsec は、アドレスの決まっていない端末から、L2TP をそのまま包んで受けます）。IPsec で守らない受け口なら、「IPsec の設定名」を空にします。 |
| V-236 | E | IPsec: 「（追加）」の列が、IKE の版 2 でない行にある・1 つ目の値が空 | 「IKE 暗号（追加）」などの「（追加）」の列は、IKE の版 2 の行だけに書きます（1 つの提案に値を並べる書き方は、版 2 のものです）。版 1 の行の 2 つ目以降の候補は、シート「IPsec 追加の提案」に 1 行ずつ書きます。版 2 の行では、1 つ目の値（「IKE 暗号」など）を先に書きます。 |
| V-237 | E | IPsec 対象通信: ポートがあるのに、プロトコルが udp・tcp でない | 「自分側ポート」「相手側ポート」を書く行は、「プロトコル」を udp か tcp にします。ポートで選ばないなら、ポートの 2 列を空にします。 |
| V-238 | E | IPsec: 方式が tunnel_if の行に「内側の VRF」がある | 「内側の VRF」のセルを空にし、守る通信の VRF は、インタフェースのシートでトンネル IF の「VRF」に書きます（トンネル IF 型の IPsec は、トンネル IF の VRF が内側です）。 |
| V-239 | E | IPsec: 方式が policy の行の「外側の VRF」が、自分側 IF の VRF と違う | 「外側の VRF」を、自分側 IF の「VRF」（インタフェースのシート）と同じにします。自分側 IF が VRF に入っていなければ、セルを空にします。 |
| V-241 | E | L2TP: 役割に要る値がない（lac の相手アドレス、lns の受け口の IF） | 役割が lac の行には「相手アドレス」（LNS のアドレス）を、lns の行には「受け口の IF」（Cisco は Virtual-Template を 1 つ、NEC IX はトンネル IF を同時につなぐ数だけ）を書きます。その IF の行は、シート「インタフェース」にも置きます。 |
| V-242 | W | L2TP: トンネルの認証が無効なのに、トンネルのパスワードがある | トンネルで相手を確かめるなら「トンネルの認証」を有効にします。確かめないなら「トンネルのパスワード」を空にします。 |
| V-243 | E | L2TP: 払い出すアドレスの先頭・末尾が片方だけ・逆。接続ユーザの L2TP が lns でない | 払い出すアドレスは、先頭と末尾の両方を、先頭 ≦ 末尾の順で書きます。接続ユーザの「L2TP の名前」は、役割が lns の行の名前にします（lac は利用者を確かめません）。 |
| V-244 | E | L2 延伸: 張り方（dynamic・manual）と、セッション ID・クッキー・パスワードが合わない。クッキーの形が違う | 張り方が manual の行には、自分と相手のセッション ID を書き、トンネルのパスワードと自分の名前を空にします。dynamic の行では、セッション ID とクッキーを空にします。クッキーは「4 54321」「8 54321 12345」のように、大きさ（4 か 8）と値を空白で区切って書きます。 |
| V-245 | E | L2 延伸: 同じ設定名で設定が違う。同じ相手・同じ回線番号の行が 2 つある | 同じ設定名の行は、送信元 IF・張り方・パスワード・名前・Hello・順序の確認・MTU の検出・DF ビットを同じ値にそろえます。変えたいなら、設定名を別の名前にします。同じ相手への回線番号は、IF ごとに別の番号にします（相手側の行も同じ番号に直します）。 |
| V-251 | W | スイッチポート・サブ IF・VLAN の IF が、VLAN の表に無い VLAN を使っている | シート「VLAN」に、その番号の行を足します。番号の方が違うなら、指摘のセルを直します。VLAN の定義を機器の設定の外（VTP など）で持っていて、表に全部を書かない決まりなら、承認します。 |
| V-252 | W | トランクのネイティブ VLAN が、許可 VLAN に入っていない | 「許可 VLAN」にネイティブ VLAN の番号を足すか、「ネイティブ VLAN」を許可 VLAN の中の番号に直します。タグなしの通信をわざと通さないなら、承認します。 |
| V-253 | E | 同じ LAG のメンバーで、束ね方（固定・LACP・PAgP）が混ざっている | 同じ LAG のメンバーの「束ね方」を、1 つの方式にそろえます（固定なら全部 on、LACP なら active か passive）。別の LAG のつもりなら、「LAG の番号」を分けます。 |
| V-254 | W | 同じ LAG のメンバーで、スイッチポートの設定（モード・VLAN）がそろっていない | 同じ LAG のメンバーの、シート「スイッチポート」の「モード」「アクセス VLAN」「ネイティブ VLAN」「許可 VLAN」を同じ値にそろえます。 |
| V-255 | E | 同じポートのサブ IF で、VLAN 番号が重なっている。タグなしの VLAN が 2 つある | 重なっているサブ IF のどちらかの「VLAN 番号（サブ IF）」を直します。「タグなしの VLAN」は、1 つのポートで 1 つのサブ IF だけにします。 |
| V-256 | W | ブリッジグループに入っている IF が、1 つだけ | 同じブリッジグループに入れる IF の行に、同じ番号を書きます。つなぐ相手が無いなら、「ブリッジグループ」を空にします。これから IF を足す途中なら、承認します。 |
