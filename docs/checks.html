チェックの一覧

このページは、プログラムが使っている定義から作っています（go run ./cmd/docgen）。手で直さないでください。

  • 重大度: E = エラー、W = 警告、I = 情報。「指定」= 案件のルールに書いた重大度
  • 頭の字: V = 値、X = 対向（2 台の間）、G = 生成、M = 移行（旧との違い・対応）、S = 外部一覧、L = 投入ログと反映確認
ID重大度内容直し方
V-101E必須の値が空指摘のセルに値を入れます。その設定が要らないなら、行ごと消します。
V-102E値の形式が型に合わない指摘のセルを、その列の書き方に直します（見出しのセルのコメントに記入例があります。アドレスは 192.0.2.1/24 の形、数は半角の数字）。
V-103E値が範囲の外指摘のセルを、範囲の中の値に直します（範囲は指摘の文と、見出しのセルのコメントにあります）。
V-104E選択肢にない語指摘のセルを、選択肢の語のどれかに直します（選べる語は指摘の文と、見出しのセルのコメントにあります）。
V-105E行のキーが重複している同じキーの行のどちらかを消すか、キーの列（機器・名前・番号など）の値を変えて別の行にします。
V-106E参照先がない（ACL 名・IF 名・回線監視の番号など）指摘のセルの名前・番号を、参照先の表にあるものに直します。参照先が無いなら、参照先の表に行を足します。その設定が要らないなら、セルを空にします。
V-107E「機器」列のホスト名が機器シートにない。@グループ名 に当たる機器が 1 台もない「機器」列を、シート「機器」にあるホスト名に直します。新しい機器なら、シート「機器」に行を足します。@グループ名 は、シート「機器」の「グループ」列にその名前を書いた機器が要ります。
V-108I定義にない見出しがある（自由列として読んだ）自由列として使うなら、そのままでかまいません。定義にある列のつもりなら、見出しの字を定義の見出し（docs/tables.md）に合わせます。
V-109E機器シートのメーカーに当たるパックがないシート「機器」の「メーカー」を、同梱のパックの ID（cisco_ios・nec_ix・nec_qx）か、案件の packs/ に置いたパックの ID に直します。
V-110W値に全角の英数字、前後の空白、制御文字が含まれる指摘のセルを打ち直します（全角の英数字を半角に、前後の空白と改行を消します）。わざとその字を使っているなら、承認します。
V-111EIF 名が、機種のポート一覧にも論理 IF の書き方にも当たらないIF 名を、その機種にあるポートの名前か、論理 IF の書き方（Loopback0・Tunnel1 など）に直します。
V-112E生成先のメーカーで書けない語指摘のセルを、生成先のメーカーが書ける語に直します（書ける語は指摘の文にあります）。どうしてもその設定が要るなら、セルを空にして追加コンフィグ（extra/）に書きます。
V-113I「明示」列が空のため、生成先の既定値で書き出す生成先の既定値でよければ、何もしません。値を決めたいなら、指摘のセルに書きます。
V-114I機種が空、または書いた機種がパックの機種の定義にない機種が分かっていれば、シート「機器」の「機種」（更改では「機器対応」の「新機種」）に、パックの機種の ID を書きます（ID は各パックの README の「機種の定義」）。定義に無い機種なら、このままで構いません（情報です。IF 名の確かめと機種の機能の確かめは行われません）。案件フォルダのパックに models.yaml を置けば、機種を足せます。
V-115W参照先がないが、参照先の表をその機器のメーカーパックがまだ読まない参照先の設定は、追加コンフィグ（extra/）に書きます。書いたら承認します。参照が要らないなら、セルを空にします。
V-116W書いた機種が、パックの機種の定義の ID に似ているが当たらない（打ち間違い）「機種」を、指摘に出ている似た ID に直します。ID が正しく、パックの定義に無い機種なら、承認します（IF 名の確かめと機種の機能の確かめは行われません）。
V-201E同じ機器・同じ VRF の中で、IF のサブネットが重なっている重なっている IF のどちらかのアドレスかプレフィックス長を直します。別の VRF に置くつもりなら、「VRF」列を埋めます。
V-202W案件の中で同じ IP アドレスが複数の IF に付いている同じアドレスを持つ IF のどちらかを直します。わざと同じにしている（冗長構成で片方だけが生きる、など）なら、承認します。
V-203EIF のアドレスがネットワークアドレスかブロードキャストアドレスIF のアドレスを、ネットワークの中のホストのアドレスに直します（/24 なら末尾が .0 と .255 は使えません）。プレフィックス長が違っていないかも見ます。
V-204Wスタティック経路のネクストホップが、その機器のどの IF のサブネットにも入らないネクストホップのアドレスか、IF のアドレス・プレフィックス長を直します。再帰の経路（別の経路で届くネクストホップ）をわざと使っているなら、承認します。
V-205E仮想 IP が、その IF のサブネットに入らない仮想 IP を、その IF のサブネットの中のアドレスに直します。IF のアドレス・プレフィックス長が違っていないかも見ます。
V-206Eホスト名に使えない文字がある・長すぎるホスト名を、英数字とハイフンだけ・63 字までに直します（ほかのシートの「機器」列も同じ名前に直します）。
V-207Eルータ ID（OSPF・BGP）が案件の中で重複している重なっているルータ ID のどちらかを、ほかの機器と違う値に直します。
V-208I有効な IF の説明が空IF の「説明」を書きます。説明を付けない決まりなら、そのままでかまいません（情報です）。
V-209Eハッシュ化された秘密の値を、別メーカーの機器に引き継ごうとしている新しいメーカーの機器には、ハッシュではなく平文の値を書きます（「形」の列を平文にして、値を入れ直します）。平文が分からないなら、新しいパスワードを決めます。
V-210WACL・プレフィックスリスト・回線監視が、定義されているがどこからも使われていない使わないなら、その行を消します。これから使うなら、使う側（IF・NAT・経路など）の列に名前を書きます。追加コンフィグから使っている・わざと残すなら、承認します。
V-211WACL に行が 1 つもない。permit の行が 1 つもないACL に行を足します。permit の行が無い ACL は全部を止めるので、わざとでなければ permit の行を足します。わざとなら、承認します。
V-212WTCP MSS 調整の値が MTU − 40 より大きいTCP MSS の値を、MTU − 40 以下に直します（MTU 1454 なら 1414）。わざと大きくしているなら、承認します。
V-213EDHCP の配布範囲・デフォルトルータがネットワークの外。配布範囲が IF のアドレスを含むDHCP の配布範囲・デフォルトルータを、プールのネットワークの中に直します。配布範囲から、IF 自身のアドレスを外します。
V-214Wスタティック経路・冗長化が参照する回線監視の送信元 IF が無効回線監視の「送信元 IF」を有効な IF に直すか、その IF を有効にします。工事の途中でわざと無効にしているなら、承認します。
V-215EIPsec の方式が tunnel_if なのにトンネル IF がない。policy なのに対象通信の行がない（相手が any の行を除く）方式が tunnel_if なら「トンネル IF」を埋めます。policy なら、シート「IPsec 対象通信」にそのトンネルの行を足します（相手が any の行は、無くてもかまいません）。方式の方が違うなら、方式を直します。
V-216W弱い暗号（des・md5・dh1・dh2・dh5）を使っている強い暗号（aes・sha256・dh14 以上）に直します。相手の機器が弱い暗号しか使えないなど、変えられない理由があるなら、理由を書いて承認します。
V-217EPPPoE の論理 IF・物理 IF がインタフェース表にないPPPoE の「論理 IF」「物理 IF」を、シート「インタフェース」にある IF 名に直します。IF の行が無いなら、足します。
V-218W秘密の値が仮の値のまま仮の値を、本当のパスワード・鍵に書き換えます。検証用にわざと仮の値で出すなら、承認します。
V-221W経路制御の方針の名前（BGP ネイバー・再配布・ポリシールーティング）が、方針の表にない方針の名前の打ち間違いなら、指摘のセルを直します。方針がまだ無いなら、シート「経路制御の方針」に行を足します。方針を追加コンフィグ（extra/）に書いているなら、承認します。
V-222W経路制御の方針が、定義されているがどこからも使われていない使うつもりの方針なら、BGP ネイバーの「受信の経路制御」「送信の経路制御」、再配布の「経路制御の条件」、IF の「ポリシールーティング」のどれかに、その名前を書きます。要らない方針なら、行を消します。表の外（追加コンフィグ）で使っているなら、承認します。
V-223WAS パスのリスト・コミュニティのリストが、どの方針からも使われていない使うつもりのリストなら、方針の「条件: AS パス」「条件: コミュニティのリスト」にその名前を書きます。要らないリストなら、行を消します。表の外（追加コンフィグ）で使っているなら、承認します。
V-224W経路制御の方針に permit の行が 1 つもない通したい経路があるなら、動作が permit の行を足します（「ほかは全部通す」なら、条件の列をすべて空にした permit の行を、いちばん大きい順番で足します）。わざと全部落としているなら、承認します。
V-225W経路制御の方針の行に、その使い道では効かない列の値があるその方針を何に使うかを決めます。ポリシールーティングなら、条件は ACL、動作はネクストホップ・出力 IF で書き、指摘の列を空にします。経路（BGP・再配布）なら、「出力 IF」「経路が無いときの…」の列を空にします。両方に使いたいときは、方針を 2 つに分けます。
V-226W経路制御の方針の行に、一緒には書けない値・使われない値がある指摘の文にある列を直します。deny の行の「付ける値」は使われないので、空にするか、動作を permit にします。コミュニティの条件は、じかの値かリストのどちらか 1 つにします。none はほかの値と一緒に書けません。
V-227EIPv6: DHCPv6 サーバが配るプレフィックス・アドレスの列の組み合わせが合わない指摘の文にある列を直します。下流へ配る「元」と「長さ」、有効時間と推奨時間は、それぞれ組で書きます。長さは、元のプレフィックスの長さ以上にします。「上流からもらったプレフィックスから配る」には、同じ機器の WAN 側の IF の「プレフィックスをもらう（DHCPv6-PD）」に書いた名前を書きます。どの列も、「DHCPv6 サーバ（名前）」のある行に書きます。
V-228ERIP: IF・再配布の行に RIP の行がない。認証の列の組み合わせ・RIPng の行に書けない列指摘の文にある列を直します。IF・再配布の行があるなら、シート「RIP」にその機器・その種類（ipv4・ipv6）の行を足します。認証は「認証」と「認証キー」を組で書き、「認証キーの番号」は md5 のときだけ書きます。版・認証は RIP（ipv4）だけの設定なので、RIPng（ipv6）の行では空にします。
V-229E回線監視: 監視先がアドレス・ネットワークの形でない。送信元アドレス・監視の出口のネクストホップが監視先と別の種類（IPv4・IPv6）監視先を、icmp ならアドレス（192.0.2.1・2001:db8::1 の形）、route ならネットワーク（192.0.2.0/24・2001:db8::/32 の形）で書きます。「送信元アドレス」「監視の出口のネクストホップ」は、監視先と同じ種類（IPv4 なら IPv4、IPv6 なら IPv6）のアドレスにします。
V-231EIPsec の自分の ID・相手の ID が「種類:値」の形でない「自分の ID」「相手の ID」を「種類:値」の形に直します。種類は address（アドレス）・fqdn（名前）・email（メールアドレスの形）・keyid（自由な文字）です。例: fqdn:rt-a01.example.com。ID を使わない（アドレスで見分ける）なら、空にします。
V-232WIPsec の行に、その IKE の版では使わない値がある指摘の列は、その行の「IKE の版」では使われません。版が正しいなら、指摘のセルを空にします（IKE のモードは版 1 だけ、PRF・相手を確かめる鍵は版 2 だけです）。値の方が正しいなら、「IKE の版」を直します。
V-233WIPsec の相手監視の再送回数・再送間隔・送り方があるのに、間隔がない相手監視を使うなら「相手監視の間隔」を書きます。使わないなら、再送回数・再送間隔・送り方のセルを空にします。
V-234EIPsec の相手アドレスが、アドレス・any・名前のどれでもない「相手アドレス」を、相手のアドレス（例 203.0.113.20）、any（相手のアドレスが決まっていない）、相手の名前（FQDN。空白なし）のどれかに直します。
V-235EL2TP の「IPsec の設定名」が指す IPsec の行が、受け口を守る形（方式 policy・相手 any・モード transport）でない「IPsec の設定名」には、L2TP の受け口を守る IPsec の行の名前を書きます。その行は、シート「IPsec」で、方式を policy、相手アドレスを any、IPsec のモードを transport にします（L2TP/IPsec は、アドレスの決まっていない端末から、L2TP をそのまま包んで受けます）。IPsec で守らない受け口なら、「IPsec の設定名」を空にします。
V-236EIPsec: 「（追加）」の列が、IKE の版 2 でない行にある・1 つ目の値が空「IKE 暗号（追加）」などの「（追加）」の列は、IKE の版 2 の行だけに書きます（1 つの提案に値を並べる書き方は、版 2 のものです）。版 1 の行の 2 つ目以降の候補は、シート「IPsec 追加の提案」に 1 行ずつ書きます。版 2 の行では、1 つ目の値（「IKE 暗号」など）を先に書きます。
V-237EIPsec 対象通信: ポートがあるのに、プロトコルが udp・tcp でない「自分側ポート」「相手側ポート」を書く行は、「プロトコル」を udp か tcp にします。ポートで選ばないなら、ポートの 2 列を空にします。
V-238EIPsec: 方式が tunnel_if の行に「内側の VRF」がある「内側の VRF」のセルを空にし、守る通信の VRF は、インタフェースのシートでトンネル IF の「VRF」に書きます（トンネル IF 型の IPsec は、トンネル IF の VRF が内側です）。
V-239EIPsec: 方式が policy の行の「外側の VRF」が、自分側 IF の VRF と違う「外側の VRF」を、自分側 IF の「VRF」（インタフェースのシート）と同じにします。自分側 IF が VRF に入っていなければ、セルを空にします。
V-241EL2TP: 役割に要る値がない（lac の相手アドレス、lns の受け口の IF）役割が lac の行には「相手アドレス」（LNS のアドレス）を、lns の行には「受け口の IF」（Cisco は Virtual-Template を 1 つ、NEC IX はトンネル IF を同時につなぐ数だけ）を書きます。その IF の行は、シート「インタフェース」にも置きます。
V-242WL2TP: トンネルの認証が無効なのに、トンネルのパスワードがあるトンネルで相手を確かめるなら「トンネルの認証」を有効にします。確かめないなら「トンネルのパスワード」を空にします。
V-243EL2TP: 払い出すアドレスの先頭・末尾が片方だけ・逆。接続ユーザの L2TP が lns でない払い出すアドレスは、先頭と末尾の両方を、先頭 ≦ 末尾の順で書きます。接続ユーザの「L2TP の名前」は、役割が lns の行の名前にします（lac は利用者を確かめません）。
V-244EL2 延伸: 張り方（dynamic・manual）と、セッション ID・クッキー・パスワードが合わない。クッキーの形が違う張り方が manual の行には、自分と相手のセッション ID を書き、トンネルのパスワードと自分の名前を空にします。dynamic の行では、セッション ID とクッキーを空にします。クッキーは「4 54321」「8 54321 12345」のように、大きさ（4 か 8）と値を空白で区切って書きます。
V-245EL2 延伸: 同じ設定名で設定が違う。同じ相手・同じ回線番号の行が 2 つある同じ設定名の行は、送信元 IF・張り方・パスワード・名前・Hello・順序の確認・MTU の検出・DF ビットを同じ値にそろえます。変えたいなら、設定名を別の名前にします。同じ相手への回線番号は、IF ごとに別の番号にします（相手側の行も同じ番号に直します）。
V-251Wスイッチポート・サブ IF・VLAN の IF が、VLAN の表に無い VLAN を使っているシート「VLAN」に、その番号の行を足します。番号の方が違うなら、指摘のセルを直します。VLAN の定義を機器の設定の外（VTP など）で持っていて、表に全部を書かない決まりなら、承認します。
V-252Wトランクのネイティブ VLAN が、許可 VLAN に入っていない「許可 VLAN」にネイティブ VLAN の番号を足すか、「ネイティブ VLAN」を許可 VLAN の中の番号に直します。タグなしの通信をわざと通さないなら、承認します。
V-253E同じ LAG のメンバーで、束ね方（固定・LACP・PAgP）が混ざっている同じ LAG のメンバーの「束ね方」を、1 つの方式にそろえます（固定なら全部 on、LACP なら active か passive）。別の LAG のつもりなら、「LAG の番号」を分けます。
V-254W同じ LAG のメンバーで、スイッチポートの設定（モード・VLAN）がそろっていない同じ LAG のメンバーの、シート「スイッチポート」の「モード」「アクセス VLAN」「ネイティブ VLAN」「許可 VLAN」を同じ値にそろえます。
V-255E同じポートのサブ IF で、VLAN 番号が重なっている。タグなしの VLAN が 2 つある重なっているサブ IF のどちらかの「VLAN 番号（サブ IF）」を直します。「タグなしの VLAN」は、1 つのポートで 1 つのサブ IF だけにします。
V-256Wブリッジグループに入っている IF が、1 つだけ同じブリッジグループに入れる IF の行に、同じ番号を書きます。つなぐ相手が無いなら、「ブリッジグループ」を空にします。これから IF を足す途中なら、承認します。
V-257E許可 VLAN の書き方が読めない「許可 VLAN」を、10,20,30-40 の形（番号と、番号-番号 の範囲。1〜4094）に直します。all・none は、それだけを書きます。
V-258EL3 のポート（routed）に、VLAN の設定があるL3 のポートとして使うなら、指摘のセル（VLAN の設定）を空にします。スイッチポートとして使うなら、「モード」を access か trunk に直します。
V-261E同じ機器・同じ VRF の中で、IF の IPv6 のサブネットが重なっている重なっている IF のどちらかの IPv6 アドレス（シート「インタフェース」）か、EUI-64 のプレフィックス（シート「IPv6 インタフェース」）を直します。別の VRF に置くつもりなら、「VRF」列を埋めます。
V-262W案件の中で同じ IPv6 アドレスが複数の IF に付いている同じ IPv6 アドレスを持つ IF のどちらかを直します。わざと同じにしている（エニーキャストなど）なら、承認します。

X-372EL2 延伸: 回線番号・張り方・セッション ID・クッキーが両端で合わない両端の「回線番号（VC ID）」と「張り方」を同じ値にそろえます。張り方が manual なら、片方の「自分のセッション ID」「自分のクッキー」を、もう片方の「相手のセッション ID」「相手のクッキー」と同じ値にします。
X-373EL2 延伸・L2TP: トンネルのパスワード・認証が両端で違う・片側だけ両端の「トンネルのパスワード」を同じ値にします。認証しないなら、両方を空に（L2TP では両方の「トンネルの認証」を無効に）します。
X-374EL2 延伸: 送信元 IF のアドレスが、相手の指す相手アドレスと違う「相手アドレス」を、相手の機器の「送信元 IF」のアドレスに合わせます。送信元 IF の方が違うなら、送信元 IF を直します。
X-375WL2TP: LAC の相手（LNS）の機器に、受ける側の行がない・名前が合わないLNS の機器のシート「L2TP」に、役割が lns の行を足します。行があるのに名前が合わないなら、LAC の「自分の名前」と LNS の「相手の名前」を同じ値にします（LNS がどの相手も受け付けるなら、「相手の名前」を空にします）。
X-381W対向: 対向の機器にその IF がない。対向の側が、別の IF を対向としているシート「インタフェース」の「対向機器」「対向 IF」を、実際につながっている相手に直します（両端の行が、互いを指すようにします）。相手の IF の行が無いなら、足します。
X-382E対向: トランクの許可 VLAN が両端で違う。対向のサブ IF の VLAN が許可 VLAN に入っていない両端の「許可 VLAN」を同じ並びにそろえます。ルータのサブ IF が相手なら、スイッチの側の「許可 VLAN」に、そのサブ IF の VLAN 番号を足します。
X-383E対向: トランクのネイティブ VLAN が両端で違う両端の「ネイティブ VLAN」を同じ番号にそろえます（空は 1）。ルータが相手なら、「タグなしの VLAN」のサブ IF の VLAN 番号に合わせます。
X-384E対向: スイッチポートのモード（アクセスとトランク）・アクセス VLAN が両端で違う両端の「モード」を、どちらも access か、どちらも trunk にそろえます。アクセスポートどうしなら、「アクセス VLAN」を同じ番号にします。わざと違う VLAN をつなぐなら、承認します。
X-385E対向: LAG の束ね方が両端で合わない。片側だけ LAG両端の「束ね方」を合わせます: 固定は両方 on、LACP は active と active か active と passive、PAgP は desirable と desirable か desirable と auto。片側だけが LAG なら、相手の側もシート「LAG のメンバー」に行を足します。
X-386W同じ番号の VLAN に、機器によって違う名前が付いている同じ番号の VLAN の名前を、機器の間でそろえます。機器ごとに名前を変える決まりなら、承認します。
X-387W対向: 速度・二重が両端で違う両端の「速度」「二重」を同じ値にそろえます（片方が固定なら、相手も同じ固定の値にします）。
X-388W対向: 片方向リンクの検出（UDLD）が片側だけ。方式が両端で違う両端のスイッチポートの「片方向リンクの検出（UDLD）」を同じ値（enable か aggressive）にそろえます。使わないなら両方を空にします。相手が UDLD を持たない機器なら、こちらも空にします。
X-391EOSPFv3: 同じ IPv6 のサブネットの IF で、エリアが違う同じ IPv6 のサブネットの IF の「エリア」（シート「OSPFv3 インタフェース」）を同じ値にそろえます。
X-392EOSPFv3: Hello・Dead 間隔が違う同じサブネットの IF の「Hello 間隔」「Dead 間隔」を同じ値にそろえます（違うと隣接できません）。
X-393EOSPFv3: 網の種類が違う同じサブネットの IF の「網の種類」を同じ値にそろえます。
X-394EOSPFv3: エリアの種類（stub・nssa）が違う両方の機器のシート「OSPFv3 エリア」で、同じエリアの「種類」を同じ値にそろえます。
X-395WOSPFv3: 片側だけ受動になっている隣接させるなら、両方の「受動」を無効にします。隣接させないつもりなら、承認します。
X-396IOSPFv3: 同じ IPv6 のサブネットで、片側だけ OSPFv3 が有効相手の IF も OSPFv3 に入れるなら、相手の機器のシート「OSPFv3 インタフェース」に行を足します。入れないつもりなら、そのままでかまいません（情報です）。
X-397EBGP（IPv6）: 相手 AS 番号が、相手機器の AS 番号と違う「相手 AS 番号」を、相手の機器の AS 番号（シート「BGP」）に合わせます。相手の機器の AS 番号の方が違うなら、そちらを直します。
X-398EBGP（IPv6）: 片側にしかネイバーの行がない相手の機器のシート「BGP IPv6 ネイバー」に、この機器の IPv6 アドレスを指す行を足します。相手が NEC IX なら IPv6 の BGP は書けないので、設計を見直します。
X-399EBGP（IPv6）: パスワードが両端で違う・片側だけ両端の「パスワード」を同じ値にします（片側だけに書いてある場合は、もう片側にも書くか、両方消します）。
X-404EOSPFv3: 認証（アルゴリズム・SPI・鍵）が両端で違う両端の IF（またはそのエリア）の OSPFv3 の「認証のアルゴリズム」「認証の SPI」「認証の鍵」を同じにします。片側にだけ認証があるなら、もう片側にも書くか、両方から外します。エリアに認証があって、その IF だけ認証しないときは、IF の「認証のアルゴリズム」を none にします（両端とも）。
X-405EVRRP: 同じグループの両端で、片方が版 3 だけ・もう片方が版 2（つながらない）どちらかにそろえます。(1) 版 3 の機器（Cisco の fhrp version vrrp v3）の、そのグループの行の「版 2 の相手とも話す」を有効にします（Cisco の vrrpv2。版 2 の相手ともつながります。NEC IX の IPv4 の VRRP は版 2 だけなので、相手が NEC IX ならこれを選びます）。(2) 版 2 の機器も版 3 にします（シート「機器」の「VRRP の版（IPv4）」を 3。書けるのは Cisco です）。(3) 版 3 の機器を版 2 に戻します（「VRRP の版（IPv4）」を空にします。Cisco は版 3 でないと IPv6 の VRRP を書けないので、シート「冗長化（IPv6 の VRRP）」のその機器の行を消すことになります）。
X-406EIPv6 の VRRP: 仮想アドレス（リンクローカル・グローバル）・広告間隔が両端で違う同じグループの「仮想リンクローカルアドレス」「仮想グローバルアドレス」「広告間隔（ミリ秒）」を、両端で同じ値にそろえます。別のグループのつもりなら、グループ番号を変えます。
X-407EEtherIP: 相手の機器のトンネルが、別の種類両端のトンネルの「種類」を同じにします。EtherIP を書けないメーカーの機器が相手なら、両端を別の方式（L2TPv3 など。シート「L2 延伸（L2TPv3）」）に作り直します。
G-601Eテンプレートの実行エラー指摘の文にある値を直します（文に、書ける値の範囲や書き方があります）。値が正しいのに出るときは、パックがその書き方を持っていません。セルを空にして、追加コンフィグ（extra/）に書きます。
G-602E設計データに値があるのに、生成に使われなかった新しい機器に持っていかないなら、指摘のセルを空にします。持っていくなら、追加コンフィグ（extra/）に新しいメーカーの書き方で書いてから、セルを空にします。
G-603E語の対応がない指摘のセルを、生成先のメーカーが書ける語に直します（書ける語は指摘の文にあります）。その語が要るなら、セルを空にして追加コンフィグに書きます。
G-604E往復の不一致（生成したコンフィグを取り込み直した結果が、設計データと違う）根拠の「設計データ」と「取り込み直し」の値を比べます。値の書き方の違いだけ（同じ意味）なら、セルを「取り込み直し」の書き方に直します。意味が違うなら、パックがその値を正しく書けていません。セルを空にして追加コンフィグに書くか、作者に知らせます（値は伏せてください）。
G-605W生成したコンフィグに、取り込み直しで未対応になる行がある生成したコンフィグのその行を、パックが読めません。追加コンフィグの行なら、承認します。パックが書いた行なら、パックの不具合なので作者に知らせます。
G-606E生成先のメーカーで必要な値が空指摘の文にある列に、値を入れます（生成先のメーカーでは、その値が無いと書けません）。
G-607E機種が対応していない機能を使っているその機能を使わない設計に変える（指摘の表の行を消す）か、機種をその機能がある機種に変えます。機種に無い機能は、パックの機種の定義（models.yaml の unsupported）に書いてあります。
G-608E追加コンフィグの実行エラー追加コンフィグ（extra/ のファイル）の、指摘の文にある行を直します（{{ }} の中の名前の打ち間違い、閉じ忘れが多いです）。
G-609W追加コンフィグの行が、パックが生成した行と二重になっている追加コンフィグから、パックが書いた行と同じ行を消します。わざと 2 回書くなら、承認します。
G-610指定案件のルール: 含むべき行がない案件のルール（rules/）が求める行が、生成したコンフィグにありません。その行が出るように、パラメータブックに値を足すか、追加コンフィグに書きます。ルールの方が古いなら、ルールを直します。
G-611指定案件のルール: 含んではいけない行がある案件のルール（rules/）が禁じる行が、生成したコンフィグにあります。その行のもとになった値をパラメータブックから直すか、追加コンフィグから消します。
G-612指定案件のルール: 式が偽・値が重複・値がそろっていない案件のルール（rules/）に合うように、指摘のセルの値を直します。ルールの方が古いなら、ルールを直します。
G-613E出力ファイル名が重複する・ファイル名に使えない文字があるホスト名を、ほかの機器と重ならず、ファイル名に使える字だけの名前に直します。
G-614Wパックが、このメーカーの書き方に置き換えて書いた設定がある指摘の文にある置き換えの内容を読みます。それでよければ、承認します。よくなければ、新しいメーカーの書き方に合う値に書き直します。
M-403E旧にあって新にない行新しい機器にも要る設定なら、パラメータブックにその行を足します（「対応」の画面で書き直すと、足りない行が入ります）。要らないなら、理由を書いて承認します。
M-404W新にあって旧にない行わざと足した設定なら、承認します。間違って入った行なら、パラメータブックから消します。
M-405W旧と新で値が違うセルわざと変えた値なら、承認します。写し間違いなら、パラメータブックのセルを旧の値に直します。
M-406EIF 対応が決まっていない旧 IF があるシート「IF 対応」の「新 IF 名」を埋めます。新しい機器に持っていかない IF なら、理由を書いて承認します。
M-407E機器対応が決まっていない旧機器があるシート「機器対応」の「新ホスト名」と「新メーカー」を埋めます。更改しない機器なら、理由を書いて承認します。
M-408E複数の旧 IF が、同じ新 IF に対応しているシート「IF 対応」で、旧 IF ごとに別々の新 IF 名を書きます。わざと 1 つにまとめるなら、理由を書いて承認します（値は先の IF のものが使われます）。
S-501W外部一覧にあって、パラメータブックにない行一覧が正しいなら、その行をパラメータブックに足します（画面の「反映」）。一覧の方が古いなら、承認します。
S-502Iパラメータブックにあって、外部一覧にない行一覧に無いだけなら、そのままでかまいません（情報です）。消すべき機器・行なら、パラメータブックから消します。
S-503E外部一覧とパラメータブックで値が違う一覧が正しいなら、画面の「反映」でパラメータブックのセルを一覧の値に書き換えます。パラメータブックが正しいなら、理由を書いて承認し、一覧を出した人に知らせます。
S-504W外部一覧の値が読めなかった一覧のそのセルを直すか、列対応（mappings/）の加工を直して、読める形にします。
S-505I外部一覧のファイルが、前回の読み込みから変わった一覧が新しくなっています。違いを見直して、要る値を反映します（情報です）。
L-701E機器に弾かれた行（エラーメッセージと、その直前のコマンド）機器の返事を読んで、弾かれた行を直します。値がその機種で使えないなら、パラメータブックを直します。追加コンフィグの行なら、extra/ のファイルを直します。パックの書き方が実機と違うなら、追加コンフィグで補い、作者に知らせます（値は伏せてください）。直したら、生成し直して流し直します。
L-702Wログのコマンドの並びが、生成したコンフィグと合わない（別の版を流した疑い）流したコンフィグが、いちばん新しい生成のものかを確かめます。古い版を流していたら、新しい版を流し直します。
L-703Wログに現れたコマンドが、生成したコンフィグより少ない（途中で切れた疑い）ログが途中で切れていないか、投入が最後まで終わったかを確かめます。切れていたら、残りを流してログを取り直します。
L-704I機器の警告メッセージ機器の警告の文を読みます。問題のない警告なら、そのままでかまいません（情報です）。
L-705Eログのプロンプトのホスト名と、流したコンフィグのホスト名・機器の対応が合わない（機器の取り違えの疑い）ログを取った機器と、流したコンフィグの機器が同じかを確かめます。別の機器に流していたら、その機器の設定を戻して、正しい機器に流し直します。ログのファイルの置き間違いなら、正しいログを置きます。
R-801Eパラメータブックにあるが、機器の設定にない行機器にその設定を入れます（流し漏れ・弾かれた行）。現地でわざと入れなかったなら、パラメータブックからその行を消して、納品物を出し直します。
R-802W機器の設定にあるが、パラメータブックにない行現地で足した設定で、残すものなら、パラメータブックにその行を足します。消し忘れた旧設定なら、機器から消します。
R-803Eパラメータブックと機器の設定で値が違う機器の値が正しい（現地で直した）なら、パラメータブックのセルを機器の値に直して、納品物を出し直します。パラメータブックが正しいなら、機器を直します。
R-804E追加コンフィグの行が、機器の設定に見つからない追加コンフィグのその行を、機器に入れます。機器が形を変えて表示しているだけなら、承認します。
R-805I機器の設定に未対応の行があり、追加コンフィグにも当たらない機器にだけある、ツールが読めない行です。要る設定なら、追加コンフィグ（extra/）に書いて残します。要らないなら、そのままでかまいません（情報です）。
R-806Eログのホスト名が、案件のどの機器にも当たらない・別の機器のものであるログのファイルが、この案件の機器のものかを確かめます。別の機器のログなら、input/logs/ から外します。ホスト名が変わったなら、シート「機器」のホスト名を見直します。
R-807I秘密の値は、機器側でハッシュ化されているため比べられなかった機器がパスワードをハッシュで持つので、ツールは比べられません。要るなら、実際にログインして確かめます（情報です）。
